# Locked decisions

Decisions that are settled and should not be re-opened by a new team without a real reason and the
user's agreement. Each entry says what was decided, why, and where the details live.

| Decision | Why | Details |
| --- | --- | --- |
| C++20 and CMake only | User requirement; modern standard library, one build system | [AGENTS.md](../AGENTS.md), `CMakeLists.txt` |
| Linux desktop target | Scope control for a toy project; no cross-platform abstractions | [AGENTS.md](../AGENTS.md) |
| No ready-made browser components (HTML/CSS/JS engines, layout engines, GUI frameworks) | The point of the project is to write them ourselves | [AGENTS.md](../AGENTS.md), [dependencies.md](dependencies.md) |
| Any third-party library needs explicit user approval | Keeps the tree portable and the project honest | [dependencies.md](dependencies.md) |
| Module boundaries: one static library per module, dependencies point downward, no cycles | Keeps modules testable and replaceable | [architecture.md](architecture.md) |
| DOM is an arena addressed by integer `NodeId`; no owning pointers or cycles | Simple lifetimes, easy dumps, safe tree links | [architecture.md](architecture.md) |
| Single process, single thread, blocking fetch in the MVP | Complexity budget; async only if it becomes a real problem | [architecture.md](architecture.md) |
| Headless-first: every feature works and is tested without a window | Enables CI, debugging and automated verification | [AGENTS.md](../AGENTS.md), [architecture.md](architecture.md) |
| Software rasterization, ARGB32 surfaces, PPM screenshots | No GPU or graphics dependencies; deterministic tests | [architecture.md](architecture.md) |
| Dumps are deterministic, line-oriented contracts (`DOM`, style, boxes) | They are the testing and debugging interface | [architecture.md](architecture.md), [roadmap.md](roadmap.md) |
| `layout` produces a pure arena `BoxTree`; text metrics arrive through a `shell`-supplied callback (no `layout` → `render` edge) | Keeps the layer boundaries and lets layout be unit-tested with a fake measurer | [architecture.md](architecture.md), [roadmap.md](roadmap.md) |
| Painting is integer-device-pixel. Since M10 the normal text path is a real font chosen automatically (8-bit freetype coverage anti-aliasing); the built-in 8x16 bitmap font with nearest-neighbour scaling and no anti-aliasing remains as the degradation path when no usable system font exists (and as the deterministic fallback the tests pin) | Deterministic fixtures and byte-identical GCC/Clang screenshots on both paths; the bitmap fallback keeps every pre-M10 output reproducible under an empty fontconfig configuration | [architecture.md](architecture.md), [roadmap.md](roadmap.md) |
| The shell fills the page canvas white; element `background-color` paints that element's box only (no canvas background propagation) | Keeps the MVP painter explicit and simple; revisit if real sites look wrong | [architecture.md](architecture.md), [roadmap.md](roadmap.md) |
| Navigation state (current URL, history, scroll offset) lives in a headless `shell::Browser`; the window event loop and `--screenshot` are thin presenters on top of it | Link clicks, history, scrolling and titles stay testable without a display | [architecture.md](architecture.md), `src/shell/include/toy/shell/browser.h` |
| Click activation: hit-test the box tree at the scrolled page point, then follow the nearest DOM ancestor element with an `href`; only `http`/`https`/`file` references navigate, fragment-only references are no-ops, and a failed load keeps the current page, scroll offset and history | Deterministic link semantics with no HTML knowledge in `layout` or `render` | [architecture.md](architecture.md) |
| Scrolling is vertical, in integer device pixels, clamped to `[0, content_height - viewport_height]`; `paint` wraps the page in a viewport `PushClip`/`PopClip` pair and translates every command by `-scroll_y`; navigation resets the offset to 0 | Minimal deterministic scrolling; scroll restoration is a documented MVP limit | [architecture.md](architecture.md), [roadmap.md](roadmap.md) |
| Platform input is normalized (left click, wheel notches, mapped keys with modifiers, `SetTitle`); `shell` owns the key bindings and scroll units | Keeps X11 details out of `shell` and page content out of `platform` | [architecture.md](architecture.md) |
| M8 uses the approved low-level libraries instead of hand-written codecs: libpng + zlib for PNG (M8a), freetype for glyphs, harfbuzz for shaping and fontconfig for font discovery (M8b) | User decision on 2026-10-31: "from scratch" means browser functionality (networking, HTML/CSS, layout, painting, JS), not low-level codecs or font machinery; the approved libraries are permissively licensed and keep M8 tractable | [dependencies.md](dependencies.md), [roadmap.md](roadmap.md) |
| M8 is split into M8a (PNG images) and M8b (real fonts) | Two smaller, independently reviewable rounds; images are independent of fonts and lower risk | [roadmap.md](roadmap.md) |
| Images paint as integer-device-pixel display-list `DrawImage` commands with a frozen nearest-neighbour source mapping and the same SrcOver formula as fills; pages without decoded images produce the pre-M8a command list unchanged | Deterministic, byte-compatible painting with no interpolation or anti-aliasing for scaled images in the MVP | [architecture.md](architecture.md), `src/render/include/toy/render/paint.h` |
| Replaced-element intrinsic sizes reach layout as a caller-supplied map keyed by DOM node id; layout never depends on render or on images | Keeps the layout → render boundary intact and layout testable with fake sizes | [architecture.md](architecture.md), `src/layout/include/toy/layout/box.h` |
| The hand-authored bitmap glyph table is reviewed visually; there is no frozen glyph-bitmap or fingerprint test | A frozen bitmap/fingerprint test would be brittle and is not worth maintaining; real-font tests likewise assert ink regions and AA presence instead of library-version-dependent coverage bytes | `src/render/font.cpp`, [handoff.md](handoff.md) |
| HTML/CSS support is an explicit subset with documented known limits | A browser toy, not a spec compliance project | [roadmap.md](roadmap.md) |
| M10: text uses automatic system font selection by default. The computed CSS `font-family` list, `font-weight` and `font-style` are matched through the approved fontconfig library (initial family `serif`), text is split into character-coverage runs so missing scripts fall back to another installed face, and the root `<html lang>` value is passed as a fontconfig language hint. `--font PATH` forces one face and `--font-family NAME` forces a preferred family (still with character fallback); with no usable font the browser degrades to the built-in bitmap font instead of failing a page load | The user asked for normal-browser font selection without manual flags (English and Chinese first); keeping the bitmap path as a degradation keeps the browser usable headless and lets tests pin every pre-M10 output byte for byte | [roadmap.md](roadmap.md), [handoff.md](handoff.md), `src/shell/include/toy/shell/fonts.h` |
| HTTP/1.1 only; TLS via the approved OpenSSL library (linked since M9); an HTTP proxy is planned as M16 but deprioritized by the user; the JavaScript subset is deferred | User priorities on 2026-10-31: HTTPS is needed to test real sites, but TLS from scratch is out of proportion, so the approved library is used; proxying is a separate small round after the planned external-stylesheet/resource-loading/CSS-compatibility arc; JS is shelved | [roadmap.md](roadmap.md), [dependencies.md](dependencies.md), [open-questions.md](open-questions.md) |
| UTF-8 input assumed (BOM stripped); no encoding detection | Keeps M2–M4 small; encodings can come later | [roadmap.md](roadmap.md) |
| One grouped commit per round; English repository files except `README.zh.md` / `docs/zh/**` | Readable history and a uniform repository | [AGENTS.md](../AGENTS.md), [conventions.md](conventions.md) |
| Real-font text is anti-aliased: freetype 8-bit glyph coverage is composited with the frozen SrcOver formula; M10 places text on a layout-provided baseline (`round(box.y) - scroll_y + round(box.baseline_offset_px)`, the line's ascent) so mixed fonts on one line share a baseline, while the bitmap path keeps top-of-cell, opaque, unaliased pixels | Gives real text a normal appearance and makes mixed-font lines correct; the bitmap fallback and its golden tests are unchanged | [architecture.md](architecture.md), `src/render/include/toy/render/paint.h`, `src/layout/include/toy/layout/box.h` |
| The effective real-font size is clamped to `kMaxRealFontSizePx` (4096 px) for metrics, shaping and rasterization | Adversarial CSS font sizes must not make freetype allocate unbounded glyph coverage bitmaps; clamping keeps layout and painting consistent and memory bounded | `src/render/include/toy/render/font.h`, [roadmap.md](roadmap.md) |
| M10 supersedes the M8b one-face-per-session rule: one `Fonts` selection per session resolves every computed text style (family list/weight/style + page language) to faces and runs; `--font PATH` forces one face for the whole session (no fallback), `--font-family NAME` forces the preferred family with character fallback; face 0 of a matched file is used, unknown families fall back instead of failing | M8b needed one face per session because only whole-page selection existed; M10's automatic selection is the normal-browser behavior the user asked for, while the explicit flags stay simple deterministic overrides | [architecture.md](architecture.md), `src/shell/include/toy/shell/fonts.h` |
| M9 (done) is a minimal HTTP/1.1-over-TLS slice: fetch absolute `https://` URLs with OpenSSL, always-on certificate and hostname verification against the system/default trust store (SNI included), no insecure mode, and no HTTP/2/ALPN, compression, cookies/sessions, HSTS, client certificates, TLS session reuse or HTTP caching | The user asked for "the most basic HTTPS request" with an MVP mindset; correctness of the security basics is not negotiable, everything else is deliberately out of scope | [roadmap.md](roadmap.md), [dependencies.md](dependencies.md) |
| M9 (done) keeps `FetchOptions` unchanged and reuses the existing timeout knobs: TCP connect uses `connect_timeout_ms`, the TLS handshake and TLS reads use `read_timeout_ms` | No new configuration surface for the MVP; the existing blocking `Fetch()` contract and error style stay intact | [roadmap.md](roadmap.md) |
| M9 (done) resolves redirect `Location` with `net::ResolveUrl`, allows http<->https redirect targets and rejects file targets | Reuses the tested RFC 3986 resolver instead of the older hand-written redirect parser, which keeps the change small and fixes relative/protocol-relative redirects | [roadmap.md](roadmap.md), [handoff.md](handoff.md) |
| M9 (done) TLS tests use a committed self-signed test CA plus a `localhost` leaf certificate/key and an in-process TLS loopback server; no test touches the public network | Deterministic, headless tests independent of the machine's connectivity and of public CA/rotation; test-only certificates are documented in the fixture README | [roadmap.md](roadmap.md), [handoff.md](handoff.md) |
| M9 (done) implements TLS with a process-wide `SSL_CTX` created lazily on the first https fetch, a private byte-stream abstraction (`Stream`/`SocketStream`/`TlsStream`) shared with plain HTTP, ordinary readable `Fetch` errors (no OpenSSL type in a public header), and a once-per-process `SIGPIPE` ignore in the TLS path | Keeps the public `Fetch` contract and error style unchanged, keeps the HTTP/1.1 code in one place, and makes TLS failures debuggable without leaking OpenSSL details; the SIGPIPE guard is the smallest mechanism that stops a dead peer from terminating the process | [handoff.md](handoff.md), `src/net/stream_internal.h`, `src/net/tls.cpp` |
| M10 (done) keeps fontconfig discovery inside `shell`: the public `toy/shell/fonts.h` `Fonts` pimpl object resolves the computed style + page language to candidate faces, caches candidate lists per (families, weight, slant, language) and loaded faces per file, and exposes only `MeasureText` and `Runs` (paint runs); layout still receives metrics through a callback and never depends on render/fontconfig, paint still owns no font discovery | Keeps the approved fontconfig dependency in the shell layer, one source of truth for the same font in measurement and painting, and keeps layout/paint testable without installed fonts | [architecture.md](architecture.md), `src/shell/include/toy/shell/fonts.h` |
| M10 (done) measures text with the computed text style: `MeasureText` receives `(text, ComputedStyle)`, `TextMetrics` carries `ascent_px`, and every text box on a line gets the line's maximum ascent as `baseline_offset_px` | Layout stays independent of fonts while painter and measurer can agree on per-style fonts and on a shared per-line baseline for mixed fonts/sizes | `src/layout/include/toy/layout/box.h`, [architecture.md](architecture.md) |
| M10 (done) paints real-font text through a `FontRunsProvider`: ordered, non-empty runs that concatenate exactly to the box text, placed at a pen advanced by each run's shaped width; an empty provider (or an empty run vector for a box) must reproduce the pre-M10 bitmap command list byte for byte | Keeps the display list a pure data structure, allows mixed-script runs in one text box, and preserves the frozen bitmap golden outputs and the M9 byte-compatibility gate | `src/paint/include/toy/paint/paint.h`, [handoff.md](handoff.md) |
| M10 (done) adds language-aware line breaking for readable Chinese: text is split into break units (whitespace separators; maximal non-CJK words; individual CJK characters; simplified UAX#14 prohibitions so closing punctuation never starts a line and opening punctuation never ends one), each unit an ordinary measured text box. No extra spaces between units, Latin words are never split | The MVP needs Chinese paragraphs (no spaces) to wrap and remain readable; reusing the word-level box model keeps the M5 line-breaking, line-height and baseline machinery unchanged and leaves every ASCII-only golden byte-identical | [architecture.md](architecture.md), `src/layout/text_break.cpp`, [roadmap.md](roadmap.md) |
| M10 (done) keeps font/config tests deterministic with committed self-authored fixture fonts (regular, bold, italic, tiny Han) plus generated test fontconfig configs: one fixture config (only the fixture fonts, generic families mapped to the Latin face) for auto-selection and fallback tests, and one empty config that forces the bitmap path. Tests never use installed fonts or the machine's font configuration | The same two-config setup proves both the new system-font path (deterministic geometry) and the full pre-M10 bitmap compatibility, without a "trust this font" backdoor in production code | [handoff.md](handoff.md), `tests/fixtures/fonts/README.md`, `tests/shell/CMakeLists.txt` |
| M11 (done) defaults the build to an optimised configuration (RelWithDebInfo) when no `CMAKE_BUILD_TYPE` is given, and compiles first-party targets with `-ffp-contract=off` | The browser is CPU-bound and an unoptimised default made normal pages several times slower; disabling FP contraction keeps layout geometry byte-identical across build types and GCC/Clang (verified by the full test suite and the byte-compat gates) | `CMakeLists.txt`, [conventions.md](conventions.md) |
| M11 (done) caches real-font text inside `render::Font` (private, bounded LRU): one reusable hb_font/hb_buffer per Font, a shaped-run cache (16 MiB / 16k entries) keyed by exact 26.6 size + text, and a glyph-coverage cache (32 MiB / 16k entries) keyed by glyph id + 26.6 size. Allocation failure is a cache miss; eviction never changes output; single-threaded like the documented Font contract | The measured hotspot was re-shaping every word with a fresh hb_face (defeating harfbuzz's shape-plan cache) and re-rasterizing every glyph with freetype on every frame; the caches make repeated frames O(glyphs to blit) while keeping every pixel and metric identical | `src/render/font_ttf.cpp`, `src/render/font_cache_internal.h`, [architecture.md](architecture.md) |
| M11 (done) caches font resolution and text metrics inside the shell's `Fonts` (private, bounded, single-threaded): an allocation-free resolved-style fast path with stable style ids, a text-metrics LRU (100k entries / 32 MiB, style+language+text+size) and a run LRU (100k / 16 MiB) returning (font, offset, length); the bitmap-degradation path deliberately bypasses the caches | Layout/relayout and every paint frame called `MeasureText`/`Runs` per word, rebuilding StyleKey copies and re-running per-code-point fallback; the caches make relayout and the paint-provider step cheap without changing any measurement | `src/shell/fonts.cpp`, `src/shell/include/toy/shell/fonts.h`, [handoff.md](handoff.md) |
| M11 (done) culls the display list to the viewport: background FillRect and DrawImage are emitted only when their exact device-pixel rect intersects the viewport after scroll translation, and text boxes only when their box expanded by `ceil(2 * font_size_px)` on every side intersects it (covering glyph overhang/italic/AA/rounding). Culling happens before style/image/font-run lookups, one viewport clip pair and command order are preserved, and the rendered pixels are byte-identical to an unculled list | A scroll/resize frame used to rebuild and rasterize the whole page although only ~0.4% of text boxes were visible; the change is a pure optimization with a conservative margin, and the frozen display-list contract now explicitly allows omitting provably invisible commands | `src/paint/paint.cpp`, `src/paint/include/toy/paint/paint.h`, [architecture.md](architecture.md) |
| M11 (done) fixes the window loop: an Expose repaints without relayout (SetViewport only when the window size differs from the laid-out viewport), a resize relayouts only on an actual size change, consecutive queued Expose/ConfigureNotify events are coalesced by the X11 backend (input/close events are never merged, dropped or reordered; a size-unchanged configure burst produces no event), and one `render::Surface` is reused for the session | Opening a window laid the page out twice and every ConfigureNotify in a resize drag re-laid-out and repainted; the changes remove redundant work and prevent event-queue pile-up without changing any rendered output | `src/platform/window.cpp`, `src/platform/include/toy/platform/window.h`, `src/shell/application.cpp`, [handoff.md](handoff.md) |
| M11 (done) deliberately keeps software rendering and does not add a GPU backend; the window still presents the whole surface with XPutImage (XShm/dirty-rect are future work needing a new dependency approval) | Measurements showed fill rate is not the bottleneck (system-font raster time was the same at 800x600 and 1600x1000 and was dominated by shaping/glyph work, not pixels), while GPU backends would add platform/dependency/headless-fallback complexity without fixing the measured CPU costs. Revisit only if, after these caches/culling, rasterization still exceeds the frame budget at the target size/DPI | [roadmap.md](roadmap.md), [handoff.md](handoff.md) |
| Fixture generators are committed next to the fixtures they produce (`tests/fixtures/fonts/generate_toy_test.py`, `tests/fixtures/fonts/generate_variants.py`, `tests/fixtures/images/generate.py`), are Python-standard-library only, write relative to their own directory and are deterministic; the fixture README documents how to regenerate and what the tests rely on | The fixtures are committed binary artifacts that the tests depend on; keeping the generators versioned makes them reproducible and auditable instead of relying on throwaway scripts. Regenerating must reproduce the committed content (the font generators are byte-identical; PNG bytes may follow the local zlib), and changing a fixture still requires updating its README and tests in the same change | `tests/fixtures/fonts/README.md`, `tests/fixtures/images/README.md`, [conventions.md](conventions.md) |
| M12 (done) fetches external author sheets in the shell and keeps `style` free of I/O: `shell::LoadStyledDocument()` discovers `<link rel="stylesheet">` elements in document order, filters them, resolves `href` against the page's final URL after redirects, fetches with `net::Fetch` and passes the CSS texts to the new two-arg `style::ComputeStyles(document, linked_sheets)` as `LinkedStyleSheet { link_node, text }` entries. `style` inserts each sheet at its `<link>` element's document position, interleaved with `<style>`; specificity/`!important`/inheritance/inline rules are unchanged and the one-arg overload stays exactly pre-M12. The same path is shared by normal page loading and `--dump-style`; `--dump-dom`/`--dump-body` fetch no sheets | Keeps the module boundaries (`style` = cascade policy, `shell` = resource policy) and gives document-order cascade semantics without duplicating CSS knowledge in the shell; preserving the one-arg API keeps every existing caller and golden output byte-identical | [architecture.md](architecture.md), [handoff.md](handoff.md), `src/style/include/toy/style/computed_style.h`, `src/shell/page.h` |
| M12 (done) uses a deliberately small external-sheet filter: first attribute occurrence, `rel` token list containing `stylesheet` without `alternate`, no `disabled` attribute, `media` only empty/`all`/`screen`, `type` only empty/`text/css`, non-empty trimmed `href` resolved with `net::ResolveUrl`, only 200..299 bodies, every filtered/failed/non-2xx sheet skipped silently, one fetch per occurrence (no deduplication/cache, like images), and serial loads with the default `FetchOptions` | The MVP needs real-page styling without media queries, `@import`, alternate/disabled selection or a resource cache, and the silent-skip/first-attribute semantics match the existing image contract; deduplication and keep-alive belong to the M13 resource pipeline. `media="not print, ..."` being skipped is a documented limit, not a bug | [roadmap.md](roadmap.md), [handoff.md](handoff.md), `src/shell/page.cpp` |
| M12 (done) keeps browser tests offline and deterministic: committed `tests/fixtures/css_site/` with documented expected computed values/geometry/pixels, plus a new header-only plain-HTTP loopback server `tests/support/http_server.h` for redirect, absolute-URL, final-URL-relative-resolution and request-count cases. Pre-M12 pages (no `<link>`, or only filtered/failing links) must stay byte-identical in dumps, exit status and PPM pixels; GCC/Clang outputs must stay identical | The feature changes what pages may request and renders, so the compatibility gate needs explicit no-sheet and filtered-only fixtures, and loopback-server cases must never touch the public network; this mirrors the M8a/M9 test-infrastructure pattern | [handoff.md](handoff.md), `tests/support/http_server.h`, `tests/shell/external_css_test.cpp` |
| M13 (done) adds a public `net::Client` keep-alive client and leaves the one-shot `Fetch()` byte-identical: pimpl, single-threaded, one idle HTTP/1.1 connection per origin, incremental response framing (bounded head; exact Content-Length or chunked body with trailers; read-ahead kept for the next request), persistence only for proper HTTP/1.1/1.0 rules with a length delimiter (persistent-without-delimiter is an error), transparent gzip via the approved zlib with raw and decoded bodies bounded, one retry when a stale pooled connection fails before any response byte (never on timeouts/fresh failures/after bytes), and redirects/file:// through the same pool. `Fetch()` keeps its exact request bytes and semantics (one request per connection, `Connection: close`, no `Accept-Encoding`) | The resource pipeline needs connection reuse and compression, but `Fetch()` is a frozen contract used by tests and other callers; keeping the two paths separate preserves every existing output byte-for-byte while giving the shell a modern client. | M13 (done) keeps resource policy in the shell: `LoadPage()` creates exactly one `net::Client` per load for the page, all stylesheets and all images, deduplicates image URLs per page load (one fetch/decode per serialized resolved URL; duplicates share one decoded image and intrinsic size; failed URLs remembered) and leaves stylesheet semantics at one fetch per applicable `<link>` occurrence. Deduplicating images (not stylesheets) is the smallest visible win and keeps the M12 style contract and tests unchanged; keeping the client lifetime inside one load avoids stale-cache and lifetime questions | [roadmap.md](roadmap.md), [handoff.md](handoff.md), `src/shell/page.h`, `src/shell/page.cpp` |
| M13 (done) makes keep-alive behavior testable offline: the shared loopback HTTP/TLS servers in `tests/support/` support persistent connections and expose connection/request counters (the HTTP one can force-close after a response for stale-idle tests), and `net.keep_alive`/`net.gzip`/`net.tls_keep_alive`/`shell.resource_loading` assert reuse, request counts, gzip decoding, caps, retry and image dedup deterministically. Real-page load-time measurements stay manual (machine/network dependent) and never enter CTest | Connection reuse and dedup are only observable through counters, not pixels, so the test infrastructure must count connections rather than assert wall time; the same M9/M12 pattern (Lead builds/validates shared test infrastructure before the round) applies | [handoff.md](handoff.md), `tests/support/http_server.h`, `tests/support/tls_server.h` |
| M14a (done) adds the CSS value model and keeps box percentages unresolved in style: `Length {value, unit px|percent}`, `AutoLength` margins, `LineHeight {kind normal|number|px}`, `TextAlign`, `Visibility`; style resolves `em`/`%` font-size/`rem` (root html computed size; the root's own rem uses 16px), parses hex/rgb/rgba/hsl/hsla and the full CSS named colors, maps logical properties to physical fields (horizontal-tb), inherits line-height/text-align/visibility/text-decoration-underline, and appends `min-width/min-height/max-width/max-height/line-height/text-align/visibility/text-decoration` to every `--dump-style` line. | M14 (CSS compatibility batch 1) is split into M14a (values & typography: %/rem, colors, background shorthand color, logical properties, min/max sizes, auto margins, line-height, text-align, underline, visibility; done) and M14b (box decorations & constraints: borders/border-*, box-sizing, overflow:hidden clipping, line-through/overline; planned). | M14b (done) simplifies border/decoration painting deliberately: every parsed border style paints a solid line (dashed/dotted/double/groove/ridge/inset/outset are accepted for the box model but not rendered with patterns), percentage border widths are ignored, border color alpha is kept in paint but dropped in the style dump (`#rrggbb`, currentColor resolved to the text color), and text decorations are 1px rows in the opaque text color at frozen offsets (underline baseline+1; line-through baseline - max(1, round(font_size/3)); overline box top) with text-decoration style/color components ignored | Patterns and rounded/inset borders are a rendering project of their own and not needed to make real page chrome visible; deterministic 1px rows keep the paint contract testable and byte-compatible. Each simplification is recorded as a roadmap known limit so it can be re-scoped explicitly later | [roadmap.md](roadmap.md), [handoff.md](handoff.md), `src/paint/paint.cpp` |
| M14b (done) appends a second block of style-dump fields after the M14a fields (`border-*-width/style`, `border-color`, `box-sizing`, `overflow`) and extends `text-decoration=` to space-joined tokens; the byte-compat normalization stays the single `sed -E 's/ min-width=.*$//'` slice | Appending keeps every pre-M14b regex/golden matching and keeps the byte-compat gate unchanged; M14b's fields are all after the M14a block, so one trailing slice still normalizes both batches. External CSS is the smallest functional prerequisite for real-page styling and needs no new dependency; the resource pipeline is a finite, measurable win that also speeds up later CSS work; the layout/CSS-compatibility arc is larger and is split so each round stays reviewable | [roadmap.md](roadmap.md), [handoff.md](handoff.md) |
